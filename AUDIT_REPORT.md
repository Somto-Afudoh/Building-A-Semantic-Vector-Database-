# AeroMart Semantic Search — Code Audit Report

**Reviewer perspective:** Senior data engineer reviewing the repository as an inherited, on-premise semantic-search pipeline.  
**Scope:** Every checklist item A-1 through F-4 in [CASE_STUDY.md](./CASE_STUDY.md), checked against the current repository files.  
**Audit type:** Static review. The pipeline was not executed, and the Bronze input files are not present in the repository listing. Findings about actual data values, runtime, model-download behavior in AeroMart's network, or production cost are identified as conditional or unverified rather than measured.

## Top five problems, in priority order

Severity ranks potential business impact, not a measured probability. The order reflects what AeroMart should resolve or validate first.

| Priority | Finding | Severity | Evidence | Impact on AeroMart |
|---|---|---|---|---|
| 1 | **D-2 — The pipeline does not deliver semantic search.** It stops at a Parquet directory; there is no vector database, index, or query service. | **High** | [load_gold.py:27–33](./load_gold.py); [README.md:26](./README.md); the dashed, unimplemented components in [ARCHITECTURE.md:17–19](./ARCHITECTURE.md). | The business objective—customers searching products by meaning—is not available to users. Embedding generation alone cannot retrieve or rank results. |
| 2 | **D-1 — Offline model availability is not addressed.** The script constructs the model from a hub name, with no checked-in/local artifact path or offline setup. | **High** (if model is not pre-cached) | [load_gold.py:4,19](./load_gold.py). | On a disconnected AeroMart server with no cached model, model initialization may fail and stop embedding generation. The exact outcome depends on local cache and network configuration, neither of which is specified. |
| 3 | **C-2 — The inner join can silently discard reviews with no metadata match.** There is no unmatched-row output or reconciliation gate. | **High** | [ingestion.py:39–47](./ingestion.py). | Reviews for products with late/missing metadata vanish from Silver and cannot be searched. AeroMart has no metric here to distinguish expected filtering from major data loss. |
| 4 | **B-1 — Embedding is invoked through a scalar Python UDF for each chunk.** | **High** (scaling risk) | [load_gold.py:19–29](./load_gold.py). | Inference and Python/JVM boundary overhead scale with chunk count. Large runs may be slow and resource-intensive. Exact model copies, serialization behavior, throughput, and cost depend on Spark version, worker lifecycle, hardware, and data volume; they were not measured. |
| 5 | **C-10 — There are no quality gates between layers.** Counts are printed, but no schema/key/value/vector assertions block publication. | **High** (data-integrity risk) | [ingestion.py:14–47](./ingestion.py); [transformation.py:17–104](./transformation.py); [load_gold.py:15–33](./load_gold.py). | Bad, incomplete, or incompatible data can be written as if the batch succeeded; downstream search quality and product metrics can degrade without an actionable failure signal. |

## Severity guide

- **High:** Can block the product objective, create material data loss, or allow serious integrity/privacy/operational failure if deployed as-is.
- **Medium:** Material quality, performance, privacy, or reproducibility risk that warrants a defined control before production.
- **Low:** Limited immediate impact, maintainability/documentation issue, or an optimization whose benefit depends on workload.

### B. Spark performance

| ID | Status | Evidence (file and lines) | Severity | Impact on AeroMart |
|---|---|---|---|---|
| B-1 | **Confirmed** | [load_gold.py:19,21–29](./load_gold.py): model object is constructed in driver code and `get_embedding` is a scalar `udf`; it calls `model.encode(text)` for one text value per invocation. | High | A large number of chunks means many row-level UDF calls and inference invocations, with JVM/Python and inference overhead. Do not assume an exact number of model loads: worker/closure serialization and lifecycle vary by Spark/runtime. Benchmark and validate deployment; batching (for example, a supported `pandas_udf` or partition-batched inference) is a candidate, not a guaranteed drop-in fix. |
| B-2 | **Confirmed** | [transformation.py:45–72,94](./transformation.py): Python `recursive_chunker` is registered as a regular Spark UDF and applied to each row. | Medium | Each review text has to cross the JVM/Python execution boundary for Python processing, adding serialization and per-row overhead. | B-3 | **Confirmed** | [ingestion.py:23,35,45,47](./ingestion.py); [transformation.py:80–102](./transformation.py); [load_gold.py:32](./load_gold.py). `count()` calls are actions, followed by writes or additional actions; DataFrames are not persisted. | High | Spark can reevaluate lineage across separate actions. | B-4 | **Confirmed** | [transformation.py:94–101](./transformation.py): `repartition(20)` redistributes/shuffles the fact input, then `coalesce(1)` reduces partitions before writing. | Medium | The repartition incurs shuffle cost, while the later single output partition removes write parallelism and funnels output through one task. The operations are not logically contradictory, but can work against efficient parallel writing. |
| B-5 | **Not an issue** | [ingestion.py:45](./ingestion.py); [transformation.py:81,90,101](./transformation.py); [load_gold.py:32](./load_gold.py). `coalesce(1)` is used for Silver and three transformation outputs, **not** in the embedding output write. | Medium (residual issue) | The checklist says `coalesce(1)` is used “everywhere,” which is false. However, the confirmed single-partition writes can reduce write parallelism and produce a large part file as data grows, so that subset remains a real scaling concern (see B-4). |
| B-6 | **Confirmed** | [ingestion.py:6](./ingestion.py); [transformation.py:7–10](./transformation.py); [load_gold.py:8–12](./load_gold.py): builders hardcode `local[*]`, 4 GB driver/executor settings, and other settings. | Medium | These settings are not a production cluster resource plan. Local mode runs on one host, and memory settings are startup/runtime dependent; setting a builder value does not establish that the deployed process/executor will receive that memory. Validate exact behavior on the target Spark launch method and configure resource allocation there. |
| B-7 | **Confirmed** | [ingestion.py:6](./ingestion.py); [transformation.py:10](./transformation.py); [load_gold.py:12](./load_gold.py) hardcode `spark.sql.shuffle.partitions` to `"20"`. | Medium | Twenty may over- or under-partition depending on data volume, shuffle size, and cores. | B-8 | **Confirmed** | [ingestion.py:14,26](./ingestion.py) calls `spark.read.json` without an explicit schema. | Medium | Schema inference adds work and can infer inconsistent types when source fields vary. | B-9 | **Confirmed** | Across [ingestion.py](./ingestion.py), [transformation.py](./transformation.py), and [load_gold.py](./load_gold.py), no DataFrame calls `.cache()` or `.persist()`, while several lineages are reused across actions/outputs. | Low | Repeated actions may reread/recompute shared Silver lineage. ## Review limitations and follow-up

- The audit verifies repository code and saved notebook content only; it does not establish observed data frequencies, measured runtime, model-serialization behavior, production resource utilization, or actual personal-data prevalence.
- The notebook's saved outputs show earlier execution results; in particular, the `spark.stop()` cell has no execution count while downstream cells do. Static inspection therefore supports the top-to-bottom failure finding, but this audit did not execute the notebook.
- The C-4 entity example is visible in saved demo output; it does not establish the frequency or range of markup/encoding issues across the full source.
- The exact overlap in A-8 cannot be calculated because the Bronze inputs are absent and the notebook does not join the two 200-row samples.
- For disconnected on-prem deployment, provision the pinned model artifact locally and test startup with network access disabled before declaring D-1 resolved.
- The top five are priority recommendations, not the only issues. All 46 case-study checklist IDs above have a status, evidence, severity, and AeroMart impact.
